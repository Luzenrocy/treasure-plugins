# Round 02 Review

评审角色：Review 者（独立任务清单审查）

检查输入：`round-02/draft.md`、`coverage.yaml`、requirements ledger v2、当前 `spec.md`、`plan.md`、`contracts/`、`quickstart.md` 和 `setup-tasks.sh` 输出。

## 检查结果

### R2-001（中，已修订）——跨仓库测试边界需要避免误读为宿主 GUI 代理任务

- **位置**：T019、T061、Polish 说明。
- **发现**：任务清单同时列出了 SDK/宿主源码 contract tests 和宿主手工验证。若仅阅读 T061 的“在宿主目录执行测试”，可能把它误读为代理运行宿主 GUI。
- **处理**：保留 SDK/宿主源码级单元/contract tests，因为它们是公开菜单 API 的必要自动化边界；在 T019、T059、T061 及说明中明确不执行宿主 GUI、权限、系统窗口、菜单实际点击、导入、重启和卸载验证，后者由用户执行。
- **验收**：T061 的尾句和“说明”均出现“ 不执行宿主 GUI 运行验证/由用户执行”，且 `quickstart.md` 保留用户证据路径。

### R2-002（低，已修订）——菜单内部事件名称容易被误认成插件实现依赖

- **位置**：T016、T057、coverage。
- **发现**：规格要求记录内部 `treasure-menu-event` 的兼容事实，但插件不得依赖该名称；任务应同时表达宿主内部兼容与插件侧禁用。
- **处理**：T016 明确该名称仅为宿主内部实现，T057 增加插件源码扫描门禁；coverage 将 FR-018/FR-020 和 U-009 映射到两侧任务。
- **验收**：插件菜单 adapter 和源码边界测试只允许公开 SDK API。

### R2-003（低，已修订）——US4 需要明确复用 US1 的本地文件能力

- **位置**：US4 阶段说明、依赖关系。
- **发现**：当前 US4 的实现任务集中在导出，若不说明依赖，实施者可能误以为基本绘图/显式保存被遗漏。
- **处理**：US4 目标和独立验收明确“继续支持基本图形、文字、图片、撤销/重做、缩放/平移、显式保存、重新打开以及导出”；依赖关系说明 US4 复用 US1 的画布/App 和文件生命周期。
- **验收**：T053 的验收映射同时包含基本绘图、保存/重开和导出。

## 结论

候选稿满足任务模板的阶段、任务 ID、`[P]`/`[USn]` 标签、精确路径、故事独立验收、依赖、并行机会和 MVP 要求。以上三项均已在候选稿中处理，没有遗留阻塞项，可提交审核者作最终决定。
