# 缄符册插件技术架构

版本 0.1 · 设计稿 · 2026-11-26

## 1. 背景与决策

缄符册是 Treasure 内的本地资料库，用于保存、查找和复制 API Key、密钥、Token、密码、提示词和文本。参考原型展示了六种条目的操作与布局，正式插件在 Treasure 桌面宿主内运行，由实际的解锁、保存、复制和失败结果驱动界面。本文面向插件开发者和技术评审，文中接口与数据流程是设计，§9 的结果均待实现后验证。[交互原型](prototype/treasure-vault.html) · [Treasure 插件研发指南](../PLUGIN-DEVELOPMENT-GUIDE.md)

**设计决策。** 用 Vue + Vite 实现单页插件，用 Web Crypto 加密条目的全部业务字段，用公开 `database` API 事务性保存逐条密文和库版本。解锁后在当前页面内存中检索。用户可通过宿主文件选择器导出和恢复加密备份。首版依赖可在目标宿主验证的 SDK 和 WebView 能力，发布时固定验证过的依赖版本与最低宿主版本。

## 2. 目标与范围

- 实现创建资料库、解锁、锁定，以及六类条目的新建、搜索、筛选、详情、编辑、收藏、删除和复制。界面和宿主菜单使用「缄符册」。
- 保存成功后更新列表与详情，关闭或重启 Treasure 后可重新解锁。保存中断、版本冲突和备份恢复失败都有明确的重读或恢复路径。
- 保留原型的桌面与窄窗工作流、右下角快捷键说明和操作后的短暂反馈。首次启动进入创建或恢复流程，空库显示新建入口。移除常驻演示、样例条目及模拟保存或加密状态。[交互原型](prototype/treasure-vault.html)
- 首版范围排除云同步、共享、自动填充、自动验证凭据、自动轮换、明文导入导出和主密码找回。主密码修改留待独立的密钥迁移方案。

## 3. 存储方案比较

| 方案 | 收益与代价 | 结论 |
| --- | --- | --- |
| 宿主数据库存明文并执行 SQL 搜索 | 查询直接，数据库副本、日志和备份的泄露后果较大。 | 放弃，业务字段在落盘前加密。 |
| 一个密文包写入插件私有存储 | 读取和导出简单，每次写入要重写全库。公开 `storage.write({ key, data })` 没有条件更新的参数，原子覆盖和断电行为也缺少公开承诺。另加数据库指针就需要协调双写与残留文件。 | 放弃作为首版主存储。同仓先写文件再写元数据的代码说明了两个操作各自成功或失败的问题。 |
| SQLite 逐条密文，事务推进库版本 | 写入量随单条大小增长，库版本和条目原子提交并可做条件写。解锁后要解密遍历，排序和搜索由页面完成。持久层仍会暴露条目数量和密文长度。 | **采用。** 容量上限、分页与宿主压测控制解锁开销。 |

## 5. 交互与视觉

### 5.1 条目与操作

| 类型标识 | 显示名 | 类型字段 | 默认详情 |
| --- | --- | --- | --- |
| `api-key` | API Key | 服务接口凭据 | 遮罩 |
| `secret-key` | 密钥 | 独立的加密或签名密钥 | 遮罩 |
| `token` | Token | 访问令牌 | 遮罩 |
| `password` | 密码 | 密码值及独立的可选账号 | 密码遮罩，账号可见 |
| `prompt` | 提示词 | 多行提示词内容 | 展示原文 |
| `text` | 文本 | 多行文本内容 | 展示原文 |

各类条目共享标题、标签、备注、收藏和更新时间。首版保留原型的单行敏感值输入及其上限，适用于单行密钥材料。切换类型时只保留适用字段，涉及把遮罩内容改为默认可见的类型时清空值并要求重新输入。密码条目的账号只属于该条目，创建或解锁资料库的主密码另行输入。[交互原型](prototype/treasure-vault.html)

四种单行凭据在遮罩和显示模式下都要在浏览器修改控件值前检查原始文本。监听 `paste`、`drop`，从剪贴板或拖放数据取文本，并在 `beforeinput` 检查其他可获得的插入文本。发现 CR 或 LF 时取消整次输入，保留控件原值并提示「凭据值只支持单行」。粘贴或拖放无法读取原始文本时，取消输入并提示重试。§6.1 的领域校验适用于所有写入和解码路径。

| 操作 | 实现约定 |
| --- | --- |
| 筛选与搜索 | 筛选全部、收藏、类型或标签，组合关键词。搜索标题、类型名、标签、备注、账号和提示词或文本正文。在解锁会话内做 NFKC 归一化与大小写折叠，所有关键词均须命中。API Key、密钥、Token 和密码值不进入搜索。按更新时间降序，同时间以 ID 排序。 |
| 编辑与删除 | 新建使用当前类型筛选作为初始类型，其他场景默认 API Key。编辑沿用 ID 和创建时间。保存成功若条目已不匹配搜索，清掉造成不匹配的条件并定位该条目。删除须确认，取消后保持条目并恢复焦点。收藏切换只在提交后更新。失败保持上一次确认状态，编辑保留草稿供处理。 |
| 快捷键 | `⌘/Ctrl + K` 聚焦搜索，搜索框内 `↑/↓` 切换选中项、`Enter` 复制当前值、`Esc` 清空查询。右下角保留「↑ ↓ 切换 · ↵ 复制」。中文输入法合成中、焦点位于表单或有弹窗时暂停对应的全局快捷键。 |
| 显示与复制 | 显式显示遮罩敏感值，最长 15 秒。选中项、筛选、搜索、视图、锁定或页面可见性变化即收起。复制不要求先显示，在用户手势内调用 `navigator.clipboard.writeText`，成功后短暂提示。能力缺失或拒绝时提供「手动复制」操作，只有再次点击才展示可选文本，关闭、到时或锁定时清空。 |
| 反馈 | 成功消息停留约 2 秒，`role="status"` 宣告通用结果。操作期间按钮呈真实待处理状态，失败在对应区域说明重试或恢复方式。通知、辅助读出和错误消息不包含值、标题或账号。 |
| 窄窗与焦点 | 以 iframe 可用宽度为准，大窗采用筛选、列表、详情三栏。`≤820px` 用筛选下拉替代侧栏，`≤560px` 在列表与详情间切换，返回后恢复列表焦点。根容器按宿主高度设 `overflow: hidden`，只让主要内容区纵向滚动。详情过长时在同一个主要滚动区完整显示，弹窗可以独立滚动。滚动条按指南使用 6px、透明轨道、`#D3D7DA` 和 3px 圆角。 |

## 6. 接口与数据

### 6.1 领域与应用接口

| 应用操作 | 输入/结果与前置条件 |
| --- | --- |
| `createVault` / `unlock` / `lock` | 首次创建用两次主密码校验，解锁验证库密钥并加载一致读，锁定撤销当前会话。启动只在状态查询成功且没有活动库时进入创建或恢复。 |
| `list` / `get` | `list` 收筛选和关键词，返回标题、类型、标签摘要、收藏、更新时间和 ID。`get` 由当前会话访问条目详情，遮罩值通过独立显示或复制命令读取。 |
| `createEntry` / `updateEntry` / `setFavorite` / `deleteEntry` | 校验输入并提交当前库 ID、基准版本与操作；更新、收藏和删除还提交已见的条目版本。返回确认后的状态或可处理的冲突、容量、读写失败。收藏传目标布尔值。 |
| `exportBackup` / `restoreBackup` | 导出要求当前会话有效，恢复要求用户确认替换及输入备份主密码；恢复只在全部校验后切换活动库。取消文件选择结束当前流程。 |

领域模型采用按 `kind` 区分的联合类型。共用 `id`（随机 UUID）、`title`、`tags`、`notes`、`favorite`、`createdAt`、`updatedAt`（UTC epoch 毫秒）。只有 `password` 有可选 `account`。API Key、密钥、Token 和密码的 `value` 拒绝含 U+000D（CR）或 U+000A（LF）的输入。提示词和文本保留提交的换行。多行编辑框的正文与打开时的控件值相同时，保存沿用原 `value`，避免只改标题时改写库内的换行。值按原文保存，须包含非空白，标题去首尾空白后必填。标题、账号、敏感值、提示词或文本、标签输入、备注建议上限依次为 90、250、5,000、12,000、170、1,000 个 UTF-16 代码单元。标签按 `,`、`，`、`、` 分隔，去掉首部 `#` 和空格，按检索规则去重并保留显示形式。创建、编辑、库内解码与备份恢复执行同一领域校验，包含类型换行规则与长度上限。[交互原型](prototype/treasure-vault.html)

### 6.2 表与密文格式

| 表 | 最小字段及约束 |
| --- | --- |
| `vault_state` | 单例 `id=1`，活动库 `active_vault_id`、仅恢复时使用的 `previous_vault_id`、每次提交唯一的 `revision`。缺行表示尚未创建，活动指针指向缺失的库表示损坏。 |
| `vault_sets` | `vault_id` 主键、`format_version`、`salt`、`kdf_iterations`、`verifier_envelope`，以及 `staging`、`ready`、`discarded` 状态。密码校验记录也是认证密文。 |
| `vault_entries` | `(vault_id, entry_id)` 主键、`entry_revision`、`envelope`。公开列只有随机标识、格式或版本控制信息与密文，标题、类型、账号、正文、标签、备注、收藏和时间均在密文内。 |

**设计决定。** v1 使用 Web Crypto `PBKDF2`（SHA-256，600,000 次，16 字节随机盐）派生不可导出的 AES-256-GCM 密钥，使用每次加密独立的 12 字节随机 IV 和 128 位认证标签。新库与恢复生成独立盐。创建时要求主密码至少 12 个 Unicode 码点、UTF-8 编码最多 1,024 字节，保持输入原文。信封使用带版本的 JSON，以 Base64 表示 IV 和含认证标签的密文，数据库参数是字符串。AAD 使用固定顺序 JSON 数组编码，条目域包含格式版本、库 ID、条目 ID 与条目版本，校验记录和备份使用独立域，备份域还绑定备份 ID 与 KDF 参数。解密前限定算法、版本、长度和 KDF 参数，v1 接受其固定迭代值。校验记录解密后验证固定内容及库 ID。条目解密后再次检查完整字段，任一条目无法验证时停止写入并进入恢复界面。同仓实现可作为 Web Crypto 接入参照，参数与信封为缄符册的设计。[同仓加密代码](../../google-authenticator/src/lib/vault.ts)

**容量预算。** 首版最多 1,000 条，单条序列化明文最多 48 KiB，全库明文最多 8 MiB。先按 UTF-8 计算再加密，备份编码后最多 16 MiB。分页先读取有界 ID 与信封长度，再按 ID 顺序分批取密文，每批最多 100 行，序列化载荷最多按 192 KiB 预算。请求也做字节数预检，给 SDK 包装留出余量。插件预算由宿主实测校准，严格遵守 256 KiB 数据库载荷、单事务 50 条、单查询 1,000 行及文件读写 32 MiB 的宿主上限。超限提示用户缩减内容，并保留已提交库。[研发指南当前契约限制](../PLUGIN-DEVELOPMENT-GUIDE.md#9-当前公开契约限制)

### 6.3 SDK 与一致性

`database.query<T>({ sql, tables, params })` 读取 `result.value.rows`，单条 `database.execute<T>(...)` 读取 `affectedRows`，`database.transaction(statements)` 按输入顺序返回每条写操作的 `affectedRows`。SQL 固定用业务表短名和 `?` 传参，`tables` 含 JOIN、CTE 和子查询访问的所有表。运行时使用单条 `SELECT` 或受支持的 `INSERT/UPDATE/DELETE`，结构 DDL 走版本化宿主脚本。数据库事务用于同一数据库内的数据更新。[SDK API 参考 §8](https://github.com/Luzenrocy/treasure-sdk/blob/main/docs/API-REFERENCE.md) · [Treasure 插件研发指南](../PLUGIN-DEVELOPMENT-GUIDE.md#42-数据库操作与版本化迁移)

1. **初始化与读取。** 查询 `vault_state`，只有成功且无行才允许创建。创建在单个事务中先在状态行缺失的条件下插入 `ready` 新库，再按 §6.4 的首次激活条件插入单例状态。两条语句各影响一行时确认创建成功。单例唯一约束保护双窗口创建，条件失效或失败后重新读取活动库。解锁读取活动标识和版本，并验证主密码。ID、字节数与密文分页查询均比较同一活动库及版本，使并发改动期间的查询停止返回跨版本数据。完成后再次核对活动库、版本和已读条目数。中途变化就丢弃本轮结果并有界重试，持续变化时提示刷新。每个成功提交都使用新版本，已用版本不会回归。
2. **写入。** 会话内命令排队。提交前校验输入和累计容量，用新的随机操作 ID 作为新库版本和被写入条目的版本。事务第一条用 `active_vault_id`、旧库版本及目标条目存在性或版本作为条件更新 `vault_state.revision`。第二条写条目，SQL 条件是活动库与第一条设置的新版本相符。新建用条件 `INSERT … SELECT`，编辑与收藏用条件 `UPDATE`，删除用条件 `DELETE`。`affectedRows=[1,1]` 后刷新内存列表并显示成功；`[0,0]` 重新载入并提示冲突，编辑保留草稿供用户对照。约束失败回滚事务。其余结果按异常处理，重读并进入保护状态。每次请求只提交一次同一个操作 ID。
3. **结果未知。** 传输失败与 SDK 返回 `ok: false` 都要走出错分支。若宿主是否提交不明，用新查询比对活动库、库版本、目标条目 ID 与条目版本。当前库版本等于操作 ID 可确认该次提交，目标条目版本也可确认仍可见的写入。删除后只在新读取确认时报告条目已经不存在。其余情形同步最新已提交状态并报告「结果未确认」。禁止自动重放；同一新建草稿保留原条目 ID，以免用户显式重试制造重复条目。
4. **结果转换。** SDK 普通失败通过 `ok` 和稳定错误码处理。`CANCELLED` 正常结束，`FILE_TOO_LARGE` 给出容量提示，`VALIDATION_FAILED` 记录脱敏诊断，`PERMISSION_DENIED` 和 `UNSUPPORTED` 提示宿主/安装问题，`IO_ERROR`、`INTERNAL` 或写入冲突按重读与恢复规则处理。应用另行捕获 Crypto、编解码及 Web API 异常。错误提示只含可执行的处理方式与安全类别，不转发未经审查的宿主错误字符串。

### 6.4 加密备份与恢复

- **选择导出目录。** 解锁时发起一次性导出，操作上下文独立于解锁会话，仅保存操作标识、起始活动库 ID、阶段、创建后 5 分钟的截止时间和匹配选择返回的短期目录引用。调用 `files.openDialog({ kind: 'directory', multiple: false })`，检查 `!Array.isArray`。若等待选择时页面隐藏，仍按 §7 撤销会话，只保留该操作。匹配的对话框结果只交付给操作上下文。页面恢复可见后，在有效的目录引用上继续原操作。取消、显式锁定、卸载、超时或引用失效均结束该操作并丢弃引用。
- **写入备份。** 在可见页面用有效会话继续导出。若旧会话已撤销，须重新认证。重新核对活动库仍与起始库 ID 相同，再按 §6.3 读取一致快照。用当前会话密钥、新 IV、独立备份 AAD 封装带版本的条目集，并携带原 KDF 盐和参数。提交前复核会话、操作有效性和活动库 ID，消费本次目录引用并调用一次 `files.writeFile({ directory, fileName, data })`。文件名以「缄符册」开头并带唯一后缀，`data` 为 `Uint8Array`。有效会话收到成功结果才报告完成。若已提交但结果不明，用户需在新会话中检查目标文件，应用不自动重写。
- **选择恢复文件。** 首次恢复与替换恢复都在读取文件和提示输入备份主密码前发起独立的一次性选择。调用 `files.openDialog({ kind: 'file', multiple: false })`，检查 `Array.isArray` 和单个选择。等待对话框或等待页面重新可见时，只在内存保留五分钟内有效的操作标识及该对话框返回的匹配文件引用。隐藏仍撤销解锁会话。取消、显式锁定、卸载、超时或引用失效时结束选择并丢弃引用。页面可见且操作有效时消费引用，调用一次 `files.readFile(file)`。读取后如流程已撤销即丢弃结果，否则检查大小、格式和 KDF，再提示输入备份主密码。开始读取后，隐藏即按 §7 撤销恢复。
- **认证与暂存。** 首次恢复及替换均采用从提交密码起最长 5 分钟的单次流程，认证成功后才授权写入。密码确认前的输入同样受 §7 的清理规则约束。逐条校验、检查重复 ID 和容量，以新库 ID 和新盐重新加密。暂存库仅由拥有其随机 ID 的恢复流程写入。每条暂存条目各用一条参数化 `INSERT INTO vault_entries (vault_id, entry_id, entry_revision, envelope) SELECT ?, ?, ?, ? WHERE EXISTS (SELECT 1 FROM vault_sets WHERE vault_id = ? AND state = ?)`。首个和第五个参数绑定同一个候选库 ID，末尾参数绑定 `staging`。条件检查与条目插入在同一 SQL 语句内执行，清理先提交时，已标为 `discarded` 或已删除的候选库均使插入影响零行。每条语句声明 `tables: ['vault_entries', 'vault_sets']`，按 §6.2 的请求字节预算拆分批次，每个 `database.transaction` 最多 50 条语句，序列化载荷遵守宿主 256 KiB 上限。批次成功时，返回的 `affectedRows` 项数须等于计划写入的条目数，且每项为 1，才继续恢复。结果不符或批次失败时停止并重读候选状态，结束本次流程。全部批次通过并完整读回验证后，用单条参数化 `UPDATE vault_sets SET state = ? WHERE vault_id = ? AND state = ?` 原子地将该库从 `staging` 改为 `ready`，仅影响一行才进入激活。影响零行时停止并重读候选状态。批次写入、标记就绪和切换前均复核短期授权。用户确认替换时记录当时的活动库 ID 和版本。
- **激活。** 每条激活语句都用 `EXISTS` 检查目标库存在且为 `ready`。首次激活用同一条参数化 `INSERT … SELECT` 检查单例状态行不存在及上述条件。替换用单条参数化 `UPDATE` 比较活动库 ID 和版本是否仍为用户确认时的值，再按上述条件切换、写入新版本，并把原活动库存为 `previous_vault_id`。新的替换会占用唯一回退位，确认时提示先保存旧库备份。恢复切换成功后重新锁定并从新库解锁。条件不成立时影响零行，重读状态、保留仍可用的库并重新确认。已提交的恢复操作结果不明时，在新的授权流程中重读候选状态及活动和回退指针。确认前保留候选库。
- **清理。** 旧库和中断的暂存库由显式清理处理。单条条件 `UPDATE` 在同一语句内检查候选库状态为 `ready` 或 `staging`，且活动与回退指针均未引用，再标为 `discarded`。分批清理条目和库记录时仍要求目标为 `discarded`，删除失败可重试。撤销回退位须独立确认并比较当前活动版本。备份文件由用户管理。
- **回退。** 当前库可解锁时，回退前导出加密备份。无法解锁或完成导出时，提示用户确认先保留当前库密文，再执行回退。用回退库的主密码完整验证该库的校验记录与全部条目，采用与恢复相同的短期授权和撤销规则。单条参数化 `UPDATE` 同时比较已确认的活动库 ID、版本和回退库 ID，并检查回退库仍存在且为 `ready`。成功时交换两个指针并创建新版本，原活动库及其中的密文保留在回退位，重新锁定并从原回退库解锁。条件失效时重读并保留两个库。[SDK 文件契约](https://github.com/Luzenrocy/treasure-sdk/blob/main/docs/API-REFERENCE.md) · [Treasure 文件与目录指南](../PLUGIN-DEVELOPMENT-GUIDE.md#33-文件目录与插件私有数据)

## 7. 安全边界与风险

| 风险 | 控制与验证责任 |
| --- | --- |
| 宿主数据库或备份文件被复制 | 条目和校验记录经认证加密。盐、随机标识、格式、条目数量和密文大小可被观察。主密码强度决定抵抗离线猜测的能力，忘记主密码后只能从持有正确密码的加密备份恢复。安全评审检查密文、备份和数据库日志中是否出现试验明文。 |
| 已解锁页面、设备或剪贴板被读取 | 日常条目的明文在解锁会话内处理。显式锁定、页面隐藏、卸载或 5 分钟无有效输入触发锁定。解除遮罩计时与整库锁定独立。锁定清除密钥引用、明文集合、索引、表单、弹窗和计时器。操作捕获会话序号，撤销后旧异步结果无权写入页面或发起新的宿主调用。已提交的宿主写入按结果不明处理。JavaScript 字符串只释放引用，系统剪贴板和历史由操作系统管理。该边界依赖可信宿主和设备。前端与 QA 核对 DOM、焦点、隐藏事件、剪贴板成功与拒绝。 |
| 页面隐藏事件在系统文件选择时触发 | 等待导出目录或恢复文件选择及重新可见时，§6.4 的一次性操作可接收匹配引用。引用限当前宿主会话且仅在内存保留。导出在选择后读取快照，恢复在有效选择返回且重新可见后读文件，再进入密码流程。已撤销会话的业务结果不得回显。QA 在目标宿主实际触发对话框、切窗和重开。 |
| 恢复或回退时处理密钥与明文 | 在可见页面独立验证备份或回退库主密码。恢复从读取文件起适用撤销规则。锁定、隐藏、卸载、取消、失败或超时即撤销对应流程，清空密码表单并释放备份密码、解密明文与密钥引用。异步读取、解密或读回返回时先检查流程有效性，立即丢弃已撤销流程的结果。撤销后停止发起批次写入、标记就绪、指针切换等调用，已经提交给宿主的操作按结果不明处理。QA 在解密后、批次间和切换前验证撤销边界。 |
| 恶意文本、损坏记录或较新数据格式 | 使用 Vue 文本渲染，拒绝超限和未知格式，禁止写入或部分展示未通过完整解锁的数据。公开的版本迁移脚本只变更结构，改变密文格式须另行设计带备份的迁移。GCM 验证每条已读取的密文及 AAD。数据库的离线删除与旧副本重放需要独立的可信状态来侦测，首版按可信宿主数据库设计。安全评审测试篡改、跨条目交换、旧副本和错误主密码。 |
| 多窗口或中途退出 | 版本校验和数据库事务保证并发写最多一方提交。可见且解锁时每 2 秒检查活动库及版本，活动库变化后锁定，普通版本变化后保留编辑草稿并刷新。页面命令提交前再次检查版本，恢复和回退同样参与条件写。QA 模拟双窗口编辑、删除、恢复、写入响应丢失和重启。 |
| 误删或卸载 | 条目删除需确认，数据库及磁盘历史副本可能还保留旧密文。卸载前导出并在独立测试库验证备份可恢复，卸载脚本只处理插件数据。发版负责人核对升级、回退、重装与外部备份保留。 |

## 8. 实施、发布与回退

### 8.1 工程与实施顺序

1. **脚手架与身份。** 以 `jian-fu-ce` 为建议工程目录和分发包名，用 `npx treasure-sdk create jian-fu-ce --alias "缄符册"` 生成 Vue + Vite 项目。`manifest.json` 声明 `alias`、菜单名「缄符册」、版本、入口、包内图标与 `minPlatformVersion`。首次 `npm run dev` 或首次打包触发脚手架身份冻结，写入含固定随机后缀的 `name` 与 `_frozen: true`，同步 `index.html` 的 `meta[name="treasure-plugin-code"]`。提交冻结后的源码标识并在包内核对 `plugin_uid`。后续更新沿用同一身份。包名独立用于分发。[研发指南 §1、§4、§7](../PLUGIN-DEVELOPMENT-GUIDE.md)
2. **依赖与宿主门槛。** 本地可用 `file:../../treasure-sdk` 联调。正式项目经 `.npmrc` 的 `@luzenrocy:registry=https://npm.pkg.github.com` 安装已发布并通过验证的精确 SDK 版本，提交 lockfile。已查阅的 SDK 文档快照 `664285a` 以 `1.0.0` 为基线并写明同名最低宿主版本，指南另记录 `files.saveDialog` 与菜单增量能力的版本条件，manifest 示例也含示例版本。首版使用 `openDialog` 目录导出与静态 manifest 菜单，开发者从选定版本的公开类型和正式宿主安装包完成联合验证后填写 `minPlatformVersion`，把 SDK 版本、宿主平台/版本和结论记入发布记录。[SDK API 参考](https://github.com/Luzenrocy/treasure-sdk/blob/main/docs/API-REFERENCE.md) · [研发指南 §3.3.2、§4、§9](../PLUGIN-DEVELOPMENT-GUIDE.md)
3. **实现顺序。** 先实现表和密文验证、事务及一致读，再实现锁定和六种条目工作流，随后接入备份、响应式主题及 README，最后做真实宿主故障注入与正式包安装。`scripts/init/<version>.sql` 使用幂等的建表和索引。已发布脚本保持固定，新增结构以更高语义版本交付。`scripts/destroy.sql` 清理插件专属表，用户导出目录和备份由用户管理。[研发指南 §2、§4.2](../PLUGIN-DEVELOPMENT-GUIDE.md)
4. **宿主联调与发包。** `npm run dev` 启动注册服务，在 Treasure 插件中心开启「插件调试入口」并注册开发地址，以宿主加载的 iframe 验证真实 SDK。宿主调试、测试与类型检查通过后执行 `npm run build`、`npm run build:plugin`、`npm run build:plugin:zip`，分别用目录包与 ZIP 从插件中心导入。包根核对 `index.html`、静态资源、manifest 和 `scripts/`。分别检查首次安装、同身份升级、重复更新、关闭重开、导出恢复、卸载与再装。浏览器单独打开开发地址不能替代宿主联调。[研发指南 §6、§7](../PLUGIN-DEVELOPMENT-GUIDE.md)

### 8.2 升级与回退

- 发布前保留上一版经过验证且身份一致的安装包和一份经恢复测试的加密备份，记录宿主版本、数据库格式、备份格式与读取兼容性。首版升级脚本只做幂等的附加结构，不重写既有 v1 密文。任一破坏格式兼容性的版本须先补完整迁移与恢复演练。
- 升级失败时保留活动库、暂停写入。若宿主支持同身份导入上一版且旧版支持现存结构，使用上一版包并重新解锁验证。若宿主拒绝版本降级，使用同身份的更高版本修复包交付旧版兼容行为。两种途径都先保留升级前的备份，避免卸载复装清空原库。
- 用户恢复切换出错、当前库无法解锁或使用错误备份时，按 §6.4 验证仍保留的旧库并条件切换。当前库无法导出时，保留其现存密文和库记录供后续处理。旧库损坏、丢失或宿主无法保留数据时，先保全可读密文与经过验证的备份，再在可用安装中走加密恢复流程。不存在可认证的密文及对应主密码时，恢复无法继续。

| 数据一致性 | 双窗口基于相同版本同时写入只允许一次提交，冲突保持草稿。分别在事务前、事务内、响应前中断，确认重读得到完整旧状态或完整新状态。容量上限和 Unicode UTF-8 计数正确，超限没有部分写入。 | 插件工程、QA |
| 备份、恢复与回退 | 验证授权取消、引用过期、Unicode 文件名、错误密码、篡改和超限文件。中断暂存批次或在切换前并发修改，原库仍可打开。验证正常恢复、回退、清理失败重试及卸载后备份可用。 | 插件工程、QA |
| 首次恢复与清理并发 | 双窗口在候选库标为 `ready` 后分别执行首次激活和清理。清理先执行时激活影响零行，即使候选库尚未删除。激活先执行时清理影响零行。两种顺序重启后分别核对状态行仍缺失或活动库可完整解锁。 | 插件工程、QA |
| 恢复批次与清理并发 | 替换恢复提交首批后暂停，在下一批写入前由另一窗口清理候选库。分别在候选库标为 `discarded` 后、候选库和已写条目全部删除后提交下一批。两种情况下该批每条语句均影响零行，恢复重读候选状态并结束，未发起标记就绪或切换。完成清理后核对候选库 ID 下无孤立条目，原活动库仍可读。 | 插件工程、QA |
| 恢复就绪与清理并发 | 在替换恢复完整读回后、标记就绪前，用另一窗口将候选库标为 `discarded` 并删除部分条目。就绪更新影响零行，恢复流程结束且候选库无法激活，原活动库继续可读。 | 插件工程、QA |
| 恢复文件选择 | 在真实宿主分别从首启和已有活动库发起恢复，让文件对话框触发隐藏。在选择有效文件并重回可见页面后，只读取一次匹配文件，再提示输入密码。分别取消选择或让旧对话框结果在操作过期后返回，核对无读取、无密码提示、无恢复写入。 | 插件工程、QA |
| 文件对话框与授权撤销 | 在真实宿主让目录对话框触发隐藏，确认可见后重新解锁并复用有效目录。取消、超时及重新认证前活动库 ID 变化时，验证没有发出写文件调用。宿主拒绝失效引用时，结束操作并丢弃引用。首启恢复在解密后、批次间和切换前分别注入锁定或隐藏，核对密码、密钥和明文引用清除，且没有新的宿主写入或切换。覆盖宿主已收到写入或切换且结果未确认的情形，在重新授权后检查文件或重读数据库指针及候选状态。 | 插件工程、安全评审、QA |
| 当前库无法导出时回退 | 模拟当前库不能解锁而回退库可完整验证。经用户确认，使用条件切换打开回退库，检查切换后的回退指针仍引用原活动库、密文逐条保持一致。并发修改基准版本时切换影响零行，两库仍可查到。 | 插件工程、安全评审、QA |
| 正式交付 | 实测公开 SDK 签名、事务返回顺序与受支持条件 SQL、最低宿主版本的文件和 Web Crypto 能力。通过真实宿主联调、类型检查、构建、目录包与 ZIP 导入和同身份升级回退。记录 manifest、入口 meta 和包身份一致。 | 插件工程、发版负责人 |
