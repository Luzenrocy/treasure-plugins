# 缄符册插件研发技术方案

版本 0.1

## 1. 实施基线

按《缄符册插件技术架构》0.1 实现首版。Vue + Vite 插件通过公开 SDK 访问 Treasure 管理的 SQLite。应用在落盘前加密每条记录的全部业务字段，解锁后在页面内存中检索，用户通过宿主文件选择器导出和恢复加密备份。首版交付创建、解锁、锁定、六类条目的管理和复制，以及备份、恢复与回退。云同步、共享、自动填充、凭据验证、自动轮换、明文导入导出、主密码找回与修改均在首版范围之外。[技术架构 §1–§4](../technical-architecture.md)

下文的目录、服务返回分类与工作包是实施约定。SDK 和宿主版本、WebView 行为、容量调优与回退保留决策在 §7 关闭。实际开发和宿主验证按 §5 排期。

## 2. 工程结构与模块契约

以 `jian-fu-ce` 为建议工程目录和分发包名，用 `npx treasure-sdk create jian-fu-ce --alias "缄符册"` 生成脚手架。manifest 声明别名、静态菜单「缄符册」、入口、包内图标、版本和最低宿主版本。第一次启动开发服务或打包时由脚手架冻结 `name` 与 `_frozen`，同步入口 `meta[name="treasure-plugin-code"]`。提交冻结后的文件，以同一身份安装与升级，核对构建包的 `plugin_uid` 与冻结身份对应。[技术架构 §8.1](../technical-architecture.md#81-工程与实施顺序) · [研发指南 §1、§4、§7](../../PLUGIN-DEVELOPMENT-GUIDE.md)

| 建议模块 | 输入与输出 | 读写边界及失败回传 |
| --- | --- | --- |
| `src/main.ts` 与 `ui/` | 挂载前调用一次 `initTreasure()`。页面将表单输入、选中项和用户动作交给应用服务，消费列表摘要、详情、待处理状态与反馈。 | 页面通过服务访问业务数据，用户文本用 Vue 文本插值。保存失败可保留有效会话内的草稿。会话撤销即卸载明文视图、弹窗与表单。 |
| `application/` | `createVault`、`unlock`、`lock` 管理会话，`list`、`get` 返回视图数据，显示与复制分别按用户动作取值。新建、编辑、收藏、删除接收草稿或目标值与基准版本，返回已确认状态或可处理结果。 | 持有当前密钥引用、快照和搜索索引。命令排队，执行时校验会话与版本。把冲突、容量、损坏、权限、未知结果映射到重读、保留草稿、恢复或重选动作。 |
| `domain/` | 按 `kind` 校验六类条目，归一化标题和标签，提供匹配、排序与容量计数输入。 | 纯函数，统一服务于创建、编辑、库内解码和备份恢复。返回字段级错误，禁止非法数据进入提交。 |
| `crypto/` | 接收密码、KDF 参数、领域对象或密文，返回非导出密钥、版本化信封或认证后的数据。 | 处理 Web Crypto 与 UTF-8、Base64、JSON 编解码。区分未知版本、格式或容量无效、认证失败，错误内容不携带输入。 |
| `repository/` | 接收库 ID、条目 ID、基准版本、密文与操作 ID，返回一致快照、按序写入回执或条件失败。 | 只接收随机标识、版本控制元数据和密文。数据读写经公开 `database` API，转换宿主失败与回执异常供服务重读。 |
| `application/backup/` 与 `host/` | 备份流程持有选择操作、候选库与阶段，适配器接收文件或目录选择请求、短期引用、文件名和字节数组。剪贴板适配器在用户手势内接收待复制文本。 | 文件操作经公开 `files` API，引用仅存于本次内存流程。剪贴板经 `navigator.clipboard.writeText`。取消正常结束，引用失效提示重选，剪贴板失败提供手动复制入口。 |
| `scripts/init/<version>.sql` 与 `scripts/destroy.sql` | 宿主安装或升级时幂等建表和索引，卸载时清理插件专属数据。 | 已发布迁移保持固定，新增结构使用更高语义版本脚本。卸载保留用户导出的外部备份。 |

运行时 SQL 使用表短名、`?` 和 `params`，每条语句的 `tables` 包括子查询、JOIN 和 CTE 访问的全部表。DDL 由宿主执行。静态依赖和图标随包交付，插件业务只使用公开 SDK 和方案约定的 Web API，禁止凭据网络请求。适配器先判断 `Result.ok`，用稳定错误码处理取消、超限、权限、引用失效和不支持等情况，另行捕获编解码、Crypto、Web API 及传输异常。诊断仅记录脱敏类别和操作阶段。[技术架构 §4、§6.3](../technical-architecture.md) · [研发指南 §2、§3、§4.2](../../PLUGIN-DEVELOPMENT-GUIDE.md) · [SDK API 参考 §2、§3、§8](https://github.com/Luzenrocy/treasure-sdk/blob/main/docs/API-REFERENCE.md)

## 3. 数据与关键流程

### 3.1 编解码与预算

`vault_state` 保存单例活动指针、回退指针与库版本，`vault_sets` 保存库级格式、KDF、校验信封与状态，`vault_entries` 按库 ID 和条目 ID 存放条目版本与密文。明文业务字段只在页面会话或已授权的恢复流程使用。持久层可观察盐、格式、随机标识、数量和密文大小。[技术架构 §6.2、§7](../technical-architecture.md)

v1 使用 PBKDF2-SHA-256 600,000 次、16 字节随机盐和不可导出的 AES-256-GCM 密钥。新建与恢复使用新盐，每次加密生成独立 12 字节 IV，认证标签为 128 位。创建主密码保留原文，校验至少 12 个 Unicode 码点、UTF-8 最大 1,024 字节。JSON 信封以 Base64 存 IV 与含认证标签的密文，用固定顺序 JSON 数组编码 AAD。条目绑定格式版本、库 ID、条目 ID 和条目版本。校验记录使用独立域并验证固定内容和库 ID。备份使用独立域并绑定备份 ID、KDF 参数。解密前拒绝未知版本、算法、超限输入与非 v1 固定迭代值，认证后按领域模型再校验。任一条目不能认证或解码时撤销写入并进入恢复界面。[技术架构 §6.1–§6.2](../technical-architecture.md)

以 UTF-8 序列化结果执行条目 48 KiB、全库 8 MiB 和备份文件 16 MiB 的预检，库最多 1,000 条。读取先取有界的 ID 和信封长度，按 ID 升序分批加载，每页最多 100 行、序列化载荷预算 192 KiB。写入也按实际序列化请求字节预检，为 SDK 包装留余量，恢复批次同时受事务最多 50 条限制。宿主硬上限为数据库载荷 256 KiB、单查询 1,000 行、文件读写 32 MiB。页面字段上限按架构 §6.1 的 UTF-16 规则，库和宿主预算按字节各自执行。[技术架构 §6.1–§6.2](../technical-architecture.md) · [研发指南 §9](../../PLUGIN-DEVELOPMENT-GUIDE.md#9-当前公开契约限制)

### 3.2 启动、读写与结果未知

1. 启动成功查询且单例缺行才显示「创建」与「恢复」。查询失败进入重试或能力提示，悬空活动指针提示损坏。创建事务先在单例缺失条件下插入 `ready` 库，再插入单例并检查目标仍为 `ready`。两条各影响一行才确认创建，其他结果重读。
2. 解锁读取活动库 ID 和版本，校验主密码，然后让 ID、长度和密文分页都带上同一库 ID 与版本条件。发布快照前再次校对活动库、版本和条目数。变化时丢弃整轮，有界重试后提示刷新。可见且解锁时每 2 秒检查版本，活动库变化即锁定，普通版本变化刷新快照并保留当前草稿。
3. 提交前核对会话、基准库 ID、库版本和容量。更新、收藏与删除传已见条目版本，收藏提交目标布尔值。一次事务先根据基准和目标条目条件把库版本改为新的随机操作 ID，再以新版本守卫写条目。写入条目使用同一个操作 ID 作为条目版本，每个操作 ID 仅发送一次。

| 两步事务结果 | 服务动作 |
| --- | --- |
| `affectedRows=[1,1]` | 有效会话内刷新确认后的列表和详情，再返回成功。 |
| `[0,0]` | 重读，提示冲突，保留有效会话内的编辑草稿。 |
| 已确认因约束失败而回滚 | 重读并报告失败，保留有效会话内的编辑草稿。 |
| 异常回执，包括 `[1,0]` 或回执形状不符 | 立即进入写入保护并重读。重读后保持保护状态，禁止写入和自动重放，界面不回报本次操作成功。 |
| 传输异常或 SDK `ok: false`，宿主是否提交未知 | 从一致快照重读活动库 ID、库版本及目标条目。活动库变化即锁定。只有同一活动库中，目标条目存在且版本等于操作 ID 时，才确认新建、编辑或收藏已写入。删除只在同一活动库确认目标缺失时报告「条目已不存在」。其余情形同步最新已提交状态并报告「结果未确认」。 |

结果未知禁止自动重放。同一新建草稿在用户确认重试时沿用条目 ID，并生成新的操作 ID。结果未知期间若会话已撤销，须重新授权并重读后才允许后续写入。[技术架构 §6.3、§7](../technical-architecture.md)

### 3.3 文件选择、恢复与回退

| 流程及前置条件 | 宿主调用与继续条件 |
| --- | --- |
| 导出目录选择 | 解锁时发起 `files.openDialog({ kind: 'directory', multiple: false })`，用 `!Array.isArray` 检查成功类型。选择操作独立保留操作 ID、起始库 ID、阶段、五分钟截止时间和匹配的短期引用。隐藏撤销解锁会话。恢复可见后，如旧会话已撤销则重新认证，并确认仍为起始活动库。 |
| 导出写入 | 读取一致快照，用当前密钥、新 IV、独立备份 AAD 和原 KDF 参数生成包。再次校验会话、活动库 ID 和操作，消费目录引用一次调用 `files.writeFile({ directory, fileName, data })`，其中 `data` 为 `Uint8Array`，文件名以「缄符册」开头并有唯一后缀。会话仍有效才显示成功，写入结果未知时由用户在新会话检查文件。 |
| 首次或替换恢复选文件 | `files.openDialog({ kind: 'file', multiple: false })` 成功后检查 `Array.isArray` 且只有一项。选择和等待重新可见期间仅保留匹配的文件引用和五分钟内有效的操作标识。可见时消费引用，调用一次 `files.readFile(file)`。读回先检查流程仍有效，再验证大小、格式和 KDF，随后提示输入备份主密码。开始读取后隐藏即撤销。 |
| 恢复认证与暂存 | 从提交密码起最多五分钟，认证成功才授权写入。完整校验领域数据、重复 ID 和容量，用新库 ID、新盐重加密。替换时由用户确认并记录当时活动库 ID 和版本，提示唯一回退位会被占用并先保存旧库备份。创建仅由本流程写入的 `staging` 候选库。 |
| 批次写入与就绪 | 每条 `INSERT … SELECT … WHERE EXISTS (...)` 在同一语句内要求该候选 ID 存在且为 `staging`，`tables` 同时含 `vault_entries` 和 `vault_sets`。批次回执数须等于计划条目数且每项为 1，任一失败或不符则停止并重读。全量读回且认证、条目数校验通过后，用单条条件 `UPDATE` 从 `staging` 变为 `ready`。恰好一行才继续，零行停止并重读。 |
| 激活候选库 | 单条 SQL 内检查候选库为 `ready`。首次用 `INSERT … SELECT` 同时检查单例缺失。替换用 `UPDATE` 同时比较已确认的活动库 ID 和版本，将原库写入回退位并生成新版本。成功后锁定，由用户解锁新库。零行时重读并重新确认。已提交结果未知时，在新授权下重读候选状态和两个指针，确认前保留候选库。 |
| 显式清理 | 单条条件 `UPDATE` 将未被活动或回退指针引用的 `staging` 或 `ready` 库标为 `discarded`。分批删条目再删库记录，每次保持 `discarded` 条件，失败可重试。撤销回退位须独立确认并比较活动版本。 |
| 回退 | 当前库可解锁时先导出加密备份。无法解锁或导出时提示用户确认保留现存密文。用回退库密码完整验证校验记录和全部条目，适用同等短期授权与撤销。条件比较确认时的活动库 ID、版本及回退库 ID，检查回退库仍为 `ready`，一次交换两指针并生成新版本。零行重读并保留两库。成功后锁定并从新活动库解锁，原活动库密文保留在回退位。 |

取消、显式锁定、卸载、超时或引用失效结束当次文件选择并丢弃引用。恢复或回退认证阶段还受隐藏、失败及取消撤销，释放密码、密钥和明文引用。每次异步返回和再次发起读写、标记就绪或切换前复核流程。撤销后丢弃旧结果，已交给宿主且未确认的写入按结果未知处理。备份由用户管理。[技术架构 §6.4、§7](../technical-architecture.md) · [SDK 文件接口 §3](https://github.com/Luzenrocy/treasure-sdk/blob/main/docs/API-REFERENCE.md)

## 4. 页面与会话

- 页面按未创建、锁定、解锁中、已解锁和保护或恢复状态渲染。已解锁空库提示新建。仅在一致快照通过完整验证后挂载明文视图。显式锁定、隐藏、卸载或 5 分钟无有效输入推进会话序号并释放密钥、明文、索引、表单和计时器。旧会话的异步回执不得更新界面或发起新的宿主调用。§3.3 的对话框选择仅允许匹配的短期引用继续流转。
- 表单包含 API Key、密钥、Token、密码、提示词和文本。仅密码有独立的可选账号。四种单行凭据在遮罩和显示控件上，通过 `paste`、`drop` 和有文本数据的 `beforeinput` 检查原始输入，发现 CR 或 LF 时整次拒绝并保留原值。取不到粘贴或拖放的原始文本时取消并提示重试。领域校验覆盖写入和解码路径。提示词和文本保留换行，正文控件内容未改时沿用原始库内值。切换到默认可见类型时清空原本遮罩的内容并要求重新输入。
- 在解锁快照内组合全部、收藏、类型或标签筛选与关键词搜索。对标题、类型名、标签、备注、账号和多行正文做 NFKC 归一化及大小写折叠，全部关键词都要命中，排除敏感凭据值。按更新时间降序、同时间按 ID 排序。新建取当前类型筛选，否则默认 API Key。保存后定位目标条目，清除导致其不可见的筛选条件。删除需确认，取消后恢复焦点。
- `⌘/Ctrl + K` 聚焦搜索，搜索框内 `↑/↓` 选中、`Enter` 复制、`Esc` 清空。右下角保留「↑ ↓ 切换 · ↵ 复制」。输入法合成、表单和弹窗状态屏蔽对应快捷键。显式显示最长 15 秒，切换选中项、筛选、搜索、视图、锁定或隐藏即收起。复制经用户手势触发，失败后须再点击手动复制才出现可选文本，关闭或计时到期即清除。真实成功展示约 2 秒，用 `role="status"` 宣告，反馈无值、标题或账号。
- iframe 宽窗显示三栏，`≤820px` 用筛选下拉，`≤560px` 切换列表与详情并在返回时还原焦点。工作区只有主内容区纵向滚动，弹窗可独立滚动，长值完整可访问。CSS 变量按架构 §5.2 实现两组色值和配比，由已验证的 WebView 主题信号切换。README 同步实际 HEX、主题面积预算、颜色意图、使用位置和宿主协调方式。正文对比度至少 4.5∶1，关键控件边界及焦点至少 3∶1。

## 6. 验收、发布与回退

QA 为每个受支持组合记录平台、宿主及 WebView 版本、SDK 和插件包版本、操作顺序、期望与实际。故障注入使用合成凭据，保留脱敏回执、活动库与回退指针、库版本、条目数和重启读回结果。主路径和停止条件以《技术架构》§9 为准。[技术架构 §9](../technical-architecture.md#9-实施验收)

| 验收组 | 可复现操作及通过条件 |
| --- | --- |
| 条目、换行、可达性 | 首启无样例，六类依次新建、查找、编辑、收藏、复制、删除。四种凭据分别在遮罩、显示控件中粘贴和拖放 CR、LF、CRLF，再以领域调用、已认证记录和备份测试拒绝；原值保留且无部分写入。提示词和文本验证编辑、只改标题和备份往返时的换行。测试输入法与右下键位、两主题下大窗、820px、560px 和更窄窗，记录焦点、滚动、短暂反馈和对比度。 |
| 保密与容量 | 错误密码、修改密文、互换记录、KDF 与容量超限、未知格式均阻止打开或部分写入。用测试值扫描数据库、WAL、备份、日志与锁屏 DOM。验证 15 秒遮罩、5 分钟空闲、页面隐藏、剪贴板拒绝及手动复制。对比 Unicode 字节阈值两侧，最低支持设备记录 KDF、满库解锁、滚动和写入耗时。 |
| 事务与恢复竞争 | 双窗口以同版本写入仅一方成功，失败方保留草稿。在请求前、事务内、响应前分别中断，重读可完整打开旧或新状态。替换恢复首批完成后，分别在清理刚标 `discarded` 和彻底移除后提交下一批，两次各语句影响零行，候选库无孤立条目且原库可读。完整读回后与清理竞争时，就绪更新影响零行。首次激活与清理分别先提交一次，被抢先的一方影响零行，重启核对状态行仍缺失或活动库完整可解锁。 |
| 异常回执与结果未知 | 注入 `[1,0]`，令活动库版本等于操作 ID，分别保留编辑目标的旧版本和令新建目标缺失。核对重读后仍处于写入保护，界面无成功提示，宿主调用无自动重放。另在丢失回执时分别验证目标版本匹配、证据不足和删除目标缺失，删除只提示「条目已不存在」。 |
| 文件生命周期与回退 | 首启和有库两种场景触发文件对话框隐藏，有效返回后只读一次再提示密码。目录选择重新可见后须重新解锁，起始库 ID 已变、取消、过期或拒绝引用时无文件写入。测试 Unicode 文件名、超限文件、错密码、篡改、正常恢复、清理重试与卸载后恢复。分别在解密后、批次间、切换前撤销，确认无后续宿主写入。响应未确认时重新授权核对文件或活动及回退指针。当前库不能导出时经确认回退，逐条核对原活动库密文保留；基准版本已变时两库均保留。 |

发布使用已验证的精确 SDK 版本和 lockfile，通过 `.npmrc` 为 `@luzenrocy` 配置 GitHub Packages。联调时 `npm run dev` 在 Treasure 中注册调试 iframe，正式验证用候选最低和目标发行宿主安装。完成测试与类型检查后执行 `npm run build`、`npm run build:plugin`、`npm run build:plugin:zip`。两种包均从插件中心导入，核对包根入口、静态资源、manifest 和 `scripts/`，以及冻结身份、meta、`plugin_uid`、`minPlatformVersion` 与发布记录的一致性。覆盖首次安装、同身份升级、重复更新、关闭重开、卸载再装及独立恢复备份。[技术架构 §8](../technical-architecture.md) · [研发指南 §6–§7](../../PLUGIN-DEVELOPMENT-GUIDE.md)

升级前保留同身份上一版包（已有发布时）和通过恢复演练的加密备份。v1 升级仅附加幂等结构，保持现有密文兼容。升级失败暂停写入并保留活动库。允许同身份降级且旧版兼容现存结构时，导入旧包并重验解锁。宿主拒绝降级时，发同身份、更高版本的兼容修复包。需要换到可用安装时先保全现存密文与已验证备份，按加密备份恢复。数据回退走 §3.3 的条件切换，升级回退保留原安装数据。[技术架构 §8.2](../technical-architecture.md#82-升级与回退)

## 7. 待定项与宿主放行条件

| --- | --- |
| [TBD] 精确 SDK、最低宿主及支持平台 | 插件工程核对已发布类型并在候选最低发行版验证 `query.value.rows`、`execute.value.affectedRows`、事务回执顺序和中途失败原子回滚。执行实际的 `INSERT … SELECT`、带 `EXISTS` 的条件 DML、零行回执、全表清单与跨批大小边界。记录结果和命令。核心契约缺失则提高最低宿主版本复测或停发。 |
