# 外部格式处理修订与仿古命名候选

## 1 修订结论与适用范围

**`.smm`、`.xmind` 统一作为外部只读来源；凡需编辑内容、调整设计或修改画布，先创建独立的原生工作文件。命名首推“会通图”，对应候选后缀 `.huitong`，正式名称与后缀仍由用户选择。**

本修订依据 2026-11-05 的补充要求，对[先前技术与 UI 方案](../../technical-ui-proposal.md)中的文件生命周期及命名假设优先适用：取消“普通单画布 SMM 可原地编辑和保存”，也取消“新增第二张画布才转存原生格式”的门槛。旧文及其批准记录保留为历史；引擎比较和宿主接入等其他议题不在本次重新决策。

`.treasuremind` 仅为旧方案和原型的后缀占位，不是已经确认的产品格式名。本文件提交六组名称、后缀与项目目录候选，不将推荐视作选定。

## 2 外部来源与原生工作文件

以下为产品应实现的文件约定；当前浏览器原型只演示交互，不能据此认定真实文件能力已完成。

| 操作 | 外部来源：`.smm` / `.xmind` | 原生工作文件 |
| --- | --- | --- |
| 打开、查看、缩放、切换已有画布 | 只读预览；不因查看产生内容修改 | 可查看，也可继续编辑 |
| 编辑节点、改主题/结构/备注、增删或重命名画布 | 先提示“创建可编辑副本”；确认后转换已支持内容至独立原生文档 | 直接修改当前原生文档 |
| 保存 | 不覆盖或写回外部来源；预览状态无“保存回源文件”路径 | 保存编辑结果；第一次保存明确选择目标文件 |
| 新建空白文件 | 不创建空白 SMM/Xmind 作为主编辑文件 | 从第一张画布开始使用原生格式 |
| 单画布 / 多画布 | 可预览已支持的来源画布 | 同一种原生格式，不因第二张画布切换后缀 |

“复制为新文件”指保留来源，另建承载编辑结果的原生文档；仅改后缀或逐字节复制外部文件都不等于完成格式转换。副本只承诺已支持内容的映射，未支持的样式、关系或附件必须说明去向，不能宣称整份来源无损可编辑。

建议沿用一个清晰的入口：“创建可编辑副本”。从预览尝试任何内容修改，也进入同一确认流程；取消则继续预览，不执行原修改、不创建文件。确认后先建立独立编辑会话，再执行修改；在首次成功写盘前仍显示未保存。取消目标选择、转换失败或写入失败均保留原文件；转换失败返回预览，写入失败保留可重试的未保存副本，不显示“已保存”。

本次将 SMM/Xmind 定位为输入格式，不要求向它们写出。原生保存与 PNG/SVG 等导出交付物各有独立用途；导出不能替代原生保存，也不清除工作文件的未保存状态。

## 3 命名方法

沿用用户为两个既有项目说明的思路：

- **石玉录**：从“他山之石可以攻玉”的启发出发，把日常笔记理解为可触发其他问题解法、帮助触类旁通的“石玉”；“录”承接记录、录用与文字载体的意味。
- **考成策**：从张居正考成法的考核、督促思路，引申为指导个人工作的工具；“策”承接策论、策略和方案的意味。

据此，思维导图名称也应遵循 **有来历的核心概念 → 对当代工具用途的引申 → 合适的载体字**。工具的重点是把零散想法展开、归类并看见联系；“图”突出可视表达，“谱”突出条理与关系。以下“图／谱”均为本次选字，不声称古籍已有同名软件或同义器物。

古籍短引只支持词根与语境，现代产品寓意另列。优缺点和推荐顺序属于本次命名判断。

## 4 六组名称与后缀候选

### A. 会通图——首选

**出处与古义。**《周易·系辞上》第八章有“而觀其會通”，语境是观察变化及其会合贯通之处。[原文](https://zh.wikisource.org/wiki/周易/繫辭上)

**现代取意。**“会”取汇集、会合，“通”取贯通、联系；把想法展开成分支，再发现知识与问题之间的关联。“图”让思考成为可见结构。三字合名为本次创制，不把古文解释为现代思维导图理论。

**优势。**既容纳梳理知识，也容纳发散思考，与石玉录强调的触类旁通相呼应，又以“图”区分记录工具。**取舍。**“会通”略偏书面，首次展示宜配“思维导图”功能说明；具体联想是否顺口仍取决于用户偏好。

### B. 纲目图——偏重结构梳理

**出处与古义。**《尚书·盘庚上》以“若網在綱，有條而不紊”作比，强调抓住纲领、条理有序；原句没有“纲目图”这个名称。[原文](https://zh.wikisource.org/wiki/尚書/盤庚上)

**现代取意。**取“纲”的统领义，配“目”的条目义重组为“纲目”；主干与分支对应纲与目，“图”呈现其结构。这是取意重组，不是直接摘取完整古称。

**优势。**层级、提纲、目录的功能联想最直接，适合课程、读书和项目拆解。**取舍。**容易让人先想到既定提纲与编目，对灵感发散和跨分支联系的表达弱于会通图。

### C. 知类谱——偏重学习与关联

**出处与古义。**《礼记·学记》有“知類通達”，处在论述学习进阶与成就的语境中。[原文](https://zh.wikisource.org/wiki/禮記/學記)

**现代取意。**“知”对应理解，“类”对应辨类与联系；“谱”取有次序地组织内容、展示关系的载体意象，构成一份可展开的知识谱系。“知类谱”是本次合成名称。

**优势。**学习意味鲜明，兼顾分类与通达，与石玉录的知识积累用途相邻。**取舍。**“谱”容易使人预期完整谱系或知识库，通用创意草图的轻巧感稍弱。

### D. 经纬图——偏重组织与连接

**出处与古义。**苏洵《谥法》卷一在“文”条列有“经纬天地曰文”，属于古代谥号评价语境，借经纬表达秩序与经营天地的意象。[原文](https://www.shidianguji.com/book/SK1158/chapter/1jpixnbsjhszu)

**现代取意。**以经线、纬线交织的视觉意象比拟思路的主线、支线与联系；“图”承接可见布局。节点和连接线是现代比喻，不是谥法原义。

**优势。**字面形象、易理解，适合强调组织复杂信息。**取舍。**地理坐标和地图联想较强，可能需要额外说明这是思维导图工具。

### E. 观象谱——偏重可视思考

**出处与古义。**《周易·系辞上》第二章有“設卦觀象”，原文属于易学的卦象与变化语境。[原文](https://zh.wikisource.org/wiki/周易/繫辭上)

**现代取意。**“观”取观察，“象”取把抽象想法显现为形象，“谱”取展开与编排关系。借此表达把思路画出来再观察、推敲；这是现代视觉思考的引申。

**优势。**古意和画面感较强，能承接图形表达的特点。**取舍。**易学、占筮或天象联想明显，普通用户未必首先想到导图；`.guanxiang` 也比其他候选更长。

### F. 类聚图——偏重归纳与收束

**出处与古义。**《周易·系辞上》第一章有“方以類聚”，同段谈事物依类聚合。[原文](https://zh.wikisource.org/wiki/周易/繫辭上)

**现代取意。**“类”是分类，“聚”是聚合；用“图”把分散信息汇成可查、可继续展开的分支。完整名称为本次组合。

**优势。**含义直观，适合读书归纳、资料整理和知识分类。**取舍。**容易偏向资料聚合器；强调同类收束多于跨类启发，与会通图相比，创意思考的空间感稍窄。

## 5 推荐次序与待选项

推荐顺序为：**会通图 ＞ 纲目图 ＞ 知类谱 ＞ 经纬图 ＞ 观象谱 ＞ 类聚图**。

首推 **会通图**：它把用途落在“让想法相会、让知识贯通”，既能表达树形整理，也给发散和建立联系留出空间；“图”又让产品形态清楚。若更希望名字一眼对应主干、分支和提纲，选 **纲目图**；若希望学习工具的气质更浓，选 **知类谱**。

**[待用户选择] 正式名称、原生后缀与项目目录尚未确定。** 若选首推方案，建议整组采用“会通图 / `.huitong` / `hui-tong-tu`”；选择其他项也按对应整组落地。文档审定不等于替用户完成命名决定。

用户选择后统一更新应用名、项目标识、文件筛选器、默认文件名、打开/保存提示与文档示例。原生容器、schema 版本和兼容迁移仍需实现与验证；决定一个后缀不等于格式已经完成。旧原型中的 `.treasuremind` 需按实际是否存在用户文件决定替换或迁移，不能靠改名假装完成转换。

## 6 落地核对

以下为本次修订的核对场景，不是已完成全部实现的报告。

| 场景 | 应观察到的结果 |
| --- | --- |
| 打开 SMM，尝试修改节点或主题 | 先创建独立原生副本；来源不产生未保存状态，不被写回 |
| 打开多画布 Xmind，只浏览和切换画布 | 保持只读；取消创建副本后继续预览，无内容修改 |
| 从只有一张画布的外部文件开始编辑 | 第一处修改前已建立原生副本，无需等第二张画布 |
| 原生文件新增第二张画布后保存、关闭、重开 | 同一后缀、同一格式恢复已支持内容与全部画布 |
| 创建或保存副本失败 | 来源不变；转换失败仍可预览，写入失败保留未保存副本供重试 |
| 检查产品命名 | 未选择前不把任何候选标成正式名；`.treasuremind` 仍注明历史占位 |
