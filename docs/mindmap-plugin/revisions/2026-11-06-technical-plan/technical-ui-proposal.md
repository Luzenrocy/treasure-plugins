# 观象谱技术与 UI 实施方案（校对版）

## 1. 结论与校对范围

观象谱应作为 Treasure 内的 Vue + TypeScript 插件交付。**正式工程唯一 SDK 基线为本地已升级的 `treasure-sdk` 2.2.0。** 必须用该 SDK 的 CLI 创建项目脚手架，再在生成工程内实施业务；不得以仓库中旧模板、原型或已有子项目的依赖版本作为脚手架或版本依据。原型所在的 2.0.0 与已有 Excalidraw 的 2.1.1 仅是历史参考，不构成兼容基线。正式工程不得把浏览器原型或 `treasure-file-adapter.ts` 当作真实 `.gxp`/`.smm`/`.xmind` 解析、目录恢复或磁盘持久化已经完成的证据。

`manifest.minPlatformVersion` 必须以 **SDK 2.2.0 CLI 生成的 manifest 契约及目标宿主联调结果**为准；不得从旧 Excalidraw 的 2.1.1 依赖或旧模板推导。发布前在目标宿主验证注册、目录授权恢复和文件调用链；验收失败时修正实现或最低宿主版本。

已确认的产品契约：

- 产品名为“观象谱”；**`.gxp` 是唯一原生、可编辑、可保存的多画布工作簿格式**。
- `.smm` 和 `.xmind` 仅是外部输入与只读预览来源。编辑必须先写出新的 `.gxp` 副本，绝不回写、覆盖或导出为来源格式。
- 无顶部标题栏；右上角是唯一的保存、导出入口；左上主菜单不得重复这两个入口。
- 文件系统边界只接受 SDK 返回的 `FileReference`/`DirectoryReference`；UI、状态和日志不得取得、存储或伪造绝对路径。

本草稿更正历史方案中 `.treasuremind`、外部格式就地编辑/写回、顶部标题栏和固定目录栏等假设。产品口径见[命名决定](../2026-11-05-native-and-naming/decision.md)与[当前交互原型 README](../../prototype/README.md)。

## 2. 已确认产品契约与更正

| 主题 | 实施契约 | 明确排除 |
| --- | --- | --- |
| 原生工作簿 | 新建、保存、另存为均面向 `.gxp`；一份工作簿含一至多张画布。 | `.treasuremind` 与单画布上限。 |
| 外部来源 | 系统“打开文件”读取 `.smm`/`.xmind`，进入只读预览；“创建可编辑副本”或首次修改先确认。 | 回写、覆盖、保存或导出为外部来源格式。 |
| 顶层控制 | 左上只有主菜单；右上唯一保存/导出；中央为撤销、重做、主题、结构。 | 顶部标题栏，或主菜单中的保存/导出副本。 |
| 左缘导航 | 左缘缩略大纲标记悬停后，以覆盖式同侧栏展示“文件/大纲”次级 Tab；浮层高于左上主菜单且不压缩画布，底部没有新建。 | 固定目录栏、左下大纲按钮、侧栏新建入口。 |
| 重置 | 重置视图只恢复缩放/平移；重置画布保留根主题、移除其余分支、保持视图、可撤销且变脏。 | 以“清空当前画布”混称两种操作。 |
| 导出 | SVG/PNG 是交付物；每个用户可改名的目标由系统另存为对话框授权；导出不清除脏状态。 | 将导出视为工作簿保存或导出为外部格式。 |

外部预览可切换已有画布、缩放和导出；不因打开 Xmind 先弹笼统兼容确认。只有用户主动点击“兼容说明”才显示范围。若真实样本不能解析，保留原会话并报告失败，不能把同格式样例树伪装成解析结果。

## 3. SDK、工程与宿主门槛

| 约束 | 实施落点 | 可核验条件 |
| --- | --- | --- |
| SDK 基线 | 使用本地 `treasure-sdk` **2.2.0** CLI 创建项目；生成后的 `package.json` 与 lockfile 锁定该版本，CI 在该依赖图运行 `tsc`。 | 对生成工程的 2.2.0 公共类型执行类型检查；不得引用 2.0.0/2.1.1 的类型快照推断 API。 |
| 工程创建与最低宿主 | 执行 `npx treasure-sdk create guan-xiang-pu --alias "观象谱"`（确保解析到本地 2.2.0 CLI），以生成的 `manifest.json` 为起点；`minPlatformVersion` 按 2.2.0 CLI 契约与目标宿主联调写入。 | 保留生成的锁文件；目标宿主完成注册调试与目录授权恢复。模板目录只可阅读参考，不得复制依赖清单。 |
| 初始化 | `src/main.ts` 在 Vue 挂载前调用 `initTreasure()`；业务只使用公开 SDK。 | 启动和类型检查无未初始化调用。 |
| 打开 | `files.openDialog({kind:'file'})` 成功后以 `Array.isArray` 收窄为 `FileReference[]`，再 `readFile(file)`。 | 成功、取消、读失败都不替换当前会话。 |
| 正常保存 | 仅当可编辑 `.gxp` 会话持有尚有效的**既有目标引用**时，编码快照后 `writeFile({file: target, data})`；不显示另存为。 | 已打开 `.gxp` 点击保存无对话框；写入使用 S-06 `WriteFileInput` 的 `file` 分支。 |
| 首次保存/另存为/导出 | 无目标的新 `.gxp`、用户另存为、以及每个 SVG/PNG 输出各调用 `saveDialog`；该调用**返回新的目标 `FileReference`**，随即交给 `writeFile`，不得持久化。多画布逐个选目标只适用于逐文件导出。 | 首次保存、另存为各一个对话框；全部画布导出每输出一个对话框；取消/失败不改会话。 |
| 工作目录 | 固定 `workspace_dir`，与 manifest `dir` 设置 `param_key` 一致。选择后 `settings.set → permissions.grantDirectory`；启动 `settings.get → verifyDirectoryGrant → directories.list`。 | 重启恢复、授权撤销、目录不可用和重选均已在目标宿主验证。 |
| Result 与边界 | 每个 SDK 调用分支 `result.ok`；`CANCELLED` 正常结束且不改会话，其他错误显示代码、说明和可行下一步。 | 不依赖异常、Tauri、宿主源码或手写桥接；覆盖 32 MiB `FILE_TOO_LARGE`。 |
| 插件工程 | 由 SDK 2.2.0 CLI 生成 Vue/Vite、SDK 初始化、manifest、生命周期与打包脚本；小写 kebab-case 工程；manifest、入口 meta 的冻结编码一致；迁移幂等，卸载不删除用户目录。 | `dev`、目录包/ZIP、安装/升级/卸载与宿主注册调试通过。 |

`saveDialog` 不是“取得当前会话引用”的 API：它是一次系统另存为选择，并返回此次选择的引用。已打开原生工作簿的当前目标来自此前 `openDialog` 或目录列举/创建成功后的 SDK 返回值，只可保留在内存会话中，不能写入设置、数据库或文件。若正常保存返回 `REFERENCE_EXPIRED`、`PERMISSION_DENIED` 或 `CONFLICT`，保留内存会话并转为用户可选的重选/另存为/重试流程，绝不静默改写其他文件。

S-07 的 2.0.0 声明没有 S-06 的 `DirectorySetting` 与 `verifyDirectoryGrant` 恢复链。原型适配器只可核对 `openDialog → readFile`、`saveDialog → writeFile` 形态，不能当成目录恢复、真实解析或真实写盘的完成证明。

## 4. 目标架构与会话不变量

```text
Vue UI / 可访问性层
  ├─ WorkspaceShell：悬浮控制、侧栏覆盖、模态与焦点归还
  ├─ CanvasController：选区、画布内核、命令与视图
  └─ SessionStore：工作簿、修订、历史、权限与忙状态
       ├─ Command service：内容命令、离开保护、异步 token
       ├─ Format service：.gxp 编解码；外部只读解析/兼容报告
       ├─ File service：打开、正常保存、另存为、副本、导出
       └─ Workspace service：目录授权、列举、移至回收站
                    └─ treasure-sdk 2.2.0
```

`SessionStore` 是唯一可写真相源，持有 `mode`、`revision`、`savedRevision`、当前画布、选区、视图、内存中的 `target?: FileReference` 与异步 generation。内容命令成功才递增 `revision`；`revision !== savedRevision` 即脏。一次写入成功只能把**实际写出的快照**标为 `savedRevision`；若写入期间已有后续修订，仍为脏。

所有打开、切换、删除和离开经同一个离开保护：提交进行中的文字/IME 编辑，创建请求 token，脏时提供保存、放弃、取消。异步结果只在 token 和目标会话仍匹配时提交。文件先在隔离缓冲区识别和解析，再替换当前会话；取消、解析/授权失败或过期结果都不替换当前文档。

画布内核、`.gxp` 编解码与外部解析都是 PoC 适配接口；原型 HTML 不能替代。PoC 要验证中文 IME、撤销/重做、缩放/拖拽、布局、销毁、SVG/PNG 导出及 WebView 焦点；不通过就收缩范围或更换实现，不能透支承诺。

## 5. 文件、目录、会话与权限流程

### 5.1 工作目录

工作目录只管理用户主动选定目录中的 `.gxp`：列举、新建、保存与删除。首次/重选时打开系统目录选择器；成功后设置目录、授权，并以授权返回目录列举。启动恢复先读设置、验证 grant、再列举；任一步失败提示重新选择并保留内存会话。不得持久化路径、子目录引用或过期 `FileReference`。

目录列表只显示 `.gxp` 可编辑工作簿。外部文件通过“打开文件”系统对话框输入，不把目录扫描宣传为外部格式管理。目录删除调用 `directories.remove`，由宿主移入系统回收站；请求发出前可取消，发出后禁用取消、遮罩关闭与返回编辑，成功才移除列表项和关闭会话。

### 5.2 打开、保存、外部副本与导出

| 触发 | 正式流程 | 成功状态 | 取消/失败 |
| --- | --- | --- | --- |
| 打开 / Cmd/Ctrl+O | 离开保护 → 选择 `.gxp/.smm/.xmind` → 读字节 → 隔离识别、校验、解析。 | `.gxp` 为可编辑会话，并在内存中持有 SDK 返回的既有目标；外部为只读预览。 | 当前会话、选中项和脏状态不变。 |
| 新建 | 创建未落盘 `.gxp` 内存工作簿；保存时选择受权目录创建或另存为。 | `editable-clean` 的未落盘草稿，`target` 为空。 | 取消命名/目标选择不伪称写盘。 |
| 正常保存 | 有 `target` 时直接 `writeFile({file: target, data: snapshot})`。 | 写入快照后 `savedRevision = snapshot.revision`。 | 保留文档与可重试状态；引用失效时不覆盖，提示另存为/重选。 |
| 首次保存 / 另存为 | 无 `target` 或用户选择另存为时，`saveDialog` 选目标；返回引用立即写入。受权目录创建用 `writeFile({directory, fileName, data})`。 | 成功返回的 `FileReference` 仅存入当前内存会话，并登记已写入快照。 | 会话与既有目标不变；取消不生成文件。 |
| 外部编辑意图 | 修改命令前确认；把已解析且允许保留的内容编码为新 `.gxp`，经另存为或受权目录创建。 | **仅在目标选择和写入均成功后**切换为新 `.gxp` 的 `editable-clean`：`savedRevision = revision`，`target` 为成功写入返回值；来源仍只读且未覆盖。 | 仍是原外部只读预览；不得执行内容修改或进入可编辑态。 |
| 导出 SVG/PNG | 渲染选定/全部画布；每个输出调用一次 `saveDialog`，用其返回引用写入。 | 逐项显示结果；不改 `savedRevision`。 | 取消不改工作簿；部分成功逐项报告并允许重试失败项。 |

副本事务的 clean 状态是关键不变量：成功写出的副本关闭时不提示保存；后续一次内容编辑才变脏并启用离开保护。对 `.smm` 与 `.xmind` 各执行一次成功、取消、写入失败回归，证明外部来源未被覆盖。

## 6. 格式、折叠状态与兼容边界

`.gxp` 是需实现和验证的版本化持久化合同，不是原型已有能力。P0 必须定稿 schema、编码/解码、损坏与超限拒绝、未知字段和资源策略，并完成“保存—关闭—重开”样本验证。最低逻辑内容含格式版本、工作簿元数据、稳定画布 ID/顺序、每画布主题树/结构/主题设置、来源元数据，以及下述折叠状态策略。具体封装和字段以可重开测试定稿。

**折叠状态契约：内容态。** 原型折叠/展开调用可撤销的 `markChanged`，首版据此把折叠写入版本化 `.gxp` schema；成功的折叠/展开命令递增 `revision`、进入撤销/重做栈并使会话变脏。保存后的重开必须恢复折叠状态；撤销/重做必须同时恢复可见分支、缩略大纲与脏状态。根主题在左右布局下保留**左右独立**折叠状态与控制，向下布局保留底部单一控制；折叠即时改变可见分支而不删除主题，缩略大纲立即同步。

| 格式 | 打开 | 编辑/保存 | 导出 | 实施前置条件 |
| --- | --- | --- | --- | --- |
| `.gxp` | 正式目标 | 编辑、正常保存或另存 `.gxp` | SVG/PNG | 编解码、折叠内容态和重开测试通过。 |
| `.smm` | 外部只读预览 | 仅先创建 `.gxp` 副本后编辑；绝不写回 | SVG/PNG | 真实样本的解析、丢失项和错误报告。 |
| `.xmind` | 外部只读预览（含已有画布切换） | 仅先创建 `.gxp` 副本后编辑；绝不写回 | SVG/PNG | 多画布、未知元素、损坏包与许可/依赖验证。 |

格式服务须逐文件说明可编辑保留、仅预览、将转换和无法保留的内容；不能识别即拒绝副本创建，不能静默丢弃。不得承诺富文本、附件、关系、概要、边界、自由主题、布局或未知元素的无损保留。

## 7. 画布、大纲与交互实现契约

- 根容器占宿主 iframe 可用高度且 `overflow: hidden`；画布是唯一主要平移/滚动区域。侧栏/对话框实际溢出时独立滚动，使用指南规定的 6px 系统风格滚动条，避免 body、根和列表多重滚动。
- 无顶部标题栏。左侧覆盖面板的层级高于左上主菜单；模态高于一般覆盖层，带遮罩和焦点约束；右上保存/导出不在主菜单重复。
- 左缘标记只表现当前可见分支；鼠标进入标记区展开同一侧栏，移开收起，且绝不改变画布宽度。文件/大纲是同侧栏等宽互斥 Tab，共享 1px 底线，选中项用整格 2px 指示条。
- 主题文字只选中节点；前置箭头是独立展开/折叠入口。节点被选中后才显示上下文工具条；点“样式”才展开属性面板。属性、抽屉和模态互斥，关闭后焦点回到仍可用触发器。

| 命令 | 模型/历史 | 视图 | 脏状态 |
| --- | --- | --- | --- |
| 重置视图 | 不写模型、不入撤销栈 | 恢复默认缩放与位置 | 不变 |
| 重置画布 | 保根、移除其他分支；一个可撤销内容命令 | 保持缩放与位置 | 变脏 |
| 新建/改名/移动 | 内容命令，入撤销栈 | 按命令同步 | 变脏 |
| 折叠/展开 | 内容命令：写入 `.gxp`、递增 `revision`、入撤销栈；根左右状态独立 | 立即更新可见分支/缩略大纲 | 变脏 |
| 导出 | 不更新工作簿模型 | 不变 | 不变 |

键盘结构命令的必要条件是：**画布已获焦、有有效节点选区、且不在文字输入或中文 IME 组合输入中**。仅在四项都满足时，`Tab` 新建所选节点的子主题，`Enter` 新建同级主题；无选区时不执行结构命令，可显示快捷键帮助或状态提示。双击节点/画布标签开始命名，`Enter` 或失焦确认、`Esc` 取消。`Cmd/Ctrl+S` 保存，`Cmd/Ctrl+Z` 撤销，`Cmd/Ctrl+O` 打开；`Esc` 依次关闭可取消浮层、属性/目录、选区。删除请求发出后，Esc、遮罩和取消均不得提前解锁。

画布外提供同步且可键盘遍历的大纲树；图标按钮有中文可访问名称和悬停提示。焦点顺序在主菜单、侧栏、画布、属性、画布标签和模态之间可预测。桌面目标 1440px，至少支持 900px；更窄时允许横向滚动，不压缩节点文字伪造适配。暖色基底配合 `#7656A7` 交互紫、`#B69CFF` 小面积焦点和 `#D36C6C` 危险色；实现逐项测量文字/焦点对比度，颜色不是唯一状态信号。

## 8. 状态、错误与安全

状态机至少有 `editable-clean`、`editable-dirty`、`external-readonly`、`opening`、`saving`、`deleting`、`error`。忙状态声明对象及可取消性；打开/保存失败可重试，删除一经发出锁定到 SDK 返回。未支持能力必须解释，不能静默成功；通知只能补充，不能替代正文错误或状态文本。

安全边界：只以 SDK 引用访问文件/目录；解析在提交会话前隔离；错误经 Vue 文本绑定呈现，不拼接 HTML；诊断不记录文件字节、路径或私密标题。原型 `postMessage` 只用于研发观察，正式插件不把它变成宿主协议或文件桥接。
