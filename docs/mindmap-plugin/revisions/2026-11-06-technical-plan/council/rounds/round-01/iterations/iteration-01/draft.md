# 观象谱技术与 UI 实施方案（校对版）

## 1. 结论与校对范围

观象谱应作为 Treasure 内的 Vue + TypeScript 插件交付；**`treasure-sdk` 2.1.1 的本地公开类型声明是正式实现、类型检查、宿主联调和发布的唯一 SDK 基线**。正式工程不得以原型接线所处的 2.0.0 环境为兼容基线，也不得把浏览器原型或 `treasure-file-adapter.ts` 当作已经完成 `.gxp`/`.smm`/`.xmind` 解析或磁盘持久化的证据。

本版校对范围是当前交互原型、文件生命周期、SDK 边界、工程交付和验收。已确认的产品契约如下：

- 产品名为“观象谱”；**`.gxp` 是唯一原生、可编辑、可保存的多画布工作簿格式**。
- `.smm`、`.xmind` 仅为外部输入和只读预览来源。对其任何内容编辑都必须先创建新的 `.gxp` 副本，绝不回写、覆盖或导出为来源格式。
- 原型是交互依据而非功能完成证明：它的目录、会话、保存、删除和兼容报告均是内存模拟；浏览器文件选择也不解析真实内容、更不保证写盘。
- 正式文件边界只能使用 SDK 返回的 `FileReference`/`DirectoryReference`；界面和业务状态均不得获得、存储、伪造绝对路径。

本草稿取代历史方案中 `.treasuremind`、外部格式原位编辑/写回、顶部标题栏和固定左侧目录等假设；历史研究中的引擎比较仅可作为 PoC 输入，不能升级为已采纳或已实现结论。[命名决定](../../../2026-11-05-native-and-naming/decision.md) 与 [当前原型 README](../../../prototype/README.md) 是本轮产品口径。

## 2. 已确认产品契约与旧方案更正

| 主题 | 本次实施决定 | 明确排除/更正 |
| --- | --- | --- |
| 原生文件 | 新建、保存、另存为均面向 `.gxp`；一份工作簿含一至多张画布。 | 不再使用 `.treasuremind`，不把单画布当作工作簿上限。 |
| 外部来源 | 通过系统“打开文件”读取 `.smm`/`.xmind`，进入只读预览；用户点“创建可编辑副本”或首次修改时确认创建 `.gxp`。 | 不回写、不覆盖、不承诺导出 `.smm`/`.xmind`。 |
| 顶层控制 | 无顶部标题栏。左上只放主菜单；右上是唯一的保存、导出入口；中央浮动组放撤销、重做、主题、结构。 | 主菜单不得复制保存或导出。 |
| 左缘导航 | 左缘常驻缩略大纲标记；悬停后覆盖式展开同一侧栏中的“文件/大纲”次级 Tab。浮层高于左上主菜单，不挤压画布，底部不放新建按钮。 | 不恢复固定目录栏、左下大纲按钮或侧栏新建入口。 |
| 视图与内容 | “重置视图”只恢复缩放、平移；“重置画布”保留根主题、删除其他分支、保持视图，并写入可撤销历史及脏状态。 | 不以“清空当前画布”混称前两种不同操作。 |
| 导出 | SVG/PNG 为交付物；每个目标文件由系统另存为对话框授权。导出不清除工作簿脏状态。 | 不把导出结果误作工作簿已保存，外部来源不导出为原格式。 |

外部只读预览可切换已有画布、缩放和导出；不应因打开 Xmind 先弹笼统兼容确认。兼容范围仅在用户主动点击“兼容说明”时展示。若格式适配层尚不能读取某一真实样本，界面必须显示失败及保留当前会话，而不能展示同格式的示例树冒充解析成功。

## 3. SDK / 插件研发约束矩阵

| 约束 | 实施落点 | 验证证据 |
| --- | --- | --- |
| SDK 2.1.1 正式基线 | `package.json` 锁定并安装 2.1.1；`manifest.minPlatformVersion` 设为能提供 2.1.1 契约的宿主版本；CI 对该版本执行 `tsc`。 | S-06 的 `DirectorySetting`、`verifyDirectoryGrant`、`saveDialog`、`Result<T>` 类型；宿主注册调试。 |
| 初始化 | `src/main.ts` 在挂载 Vue 前调用 `initTreasure()`；业务仅从公开 SDK 模块调用能力。 | 类型检查及宿主启动无未初始化错误。 |
| 文件打开 | `files.openDialog({kind:'file', filters})` 后以 `Array.isArray` 收窄、取回 `FileReference`，再 `files.readFile(reference)`。 | 成功、`CANCELLED`、读失败都保留原会话的测试。 |
| 另存为/导出 | `files.saveDialog` 取得当前会话的 `FileReference`，立即 `files.writeFile({file,data})`；不持久化此引用。多画布逐个选择目标。 | 用户改名、取消、写入失败、部分成功的宿主联调。 |
| 工作目录 | 固定权限键 `workspace_dir`（与 manifest 的 `dir` 设置 `param_key` 一致）。选择后 `settings.set` → `permissions.grantDirectory`；启动时 `settings.get` → `verifyDirectoryGrant` → `directories.list`。 | 重启恢复、撤销授权、目录移走、重选目录。 |
| SDK Result | 每次 SDK 调用都分支 `result.ok`；`CANCELLED` 正常结束且不改会话，其他错误按代码与消息反馈且可重试。 | 单元测试及 UI 错误场景。 |
| 安全边界 | 不调用 Tauri、宿主源码或手写桥接；不传绝对路径，不绕过 32 MiB 单次文件/私有存储限制。 | 静态审查、类型检查和超限错误测试。 |
| 插件契约 | 脚手架生成 Vue/Vite 工程；`manifest.json`、入口 meta 的冻结插件编码一致；迁移幂等；卸载脚本不删除用户工作目录。 | `npm run dev`、目录包/ZIP 包导入、安装/升级/卸载验证。 |

S-07 的 2.0.0 声明只有 `settings` 普通键值和 `permissions.getDirectory`，没有 2.1.1 的 `DirectorySetting`/`verifyDirectoryGrant` 恢复链。因此原型适配器可用于核对 `openDialog → readFile` 和 `saveDialog → writeFile` 的调用形态，**不能作为目录授权恢复、真实格式解析或写盘已实现的依据**。

## 4. 目标架构与模块职责

```text
Vue UI / 可访问性层
  ├─ WorkspaceShell：悬浮控制、侧栏覆盖层、模态与焦点归还
  ├─ CanvasController：画布内核适配、选区、命令与视图状态
  └─ SessionStore：工作簿、修订、撤销栈、只读/忙/错误状态
         ├─ Command service：可撤销内容命令、离开保护、异步令牌
         ├─ Format service：gxp 编解码；外部识别、只读解析、兼容报告
         ├─ File service：FileReference 打开、原生保存、另存为、导出
         └─ Workspace service：目录授权、列举、删除到回收站
                     └─ treasure-sdk 2.1.1
```

`SessionStore` 是唯一可写的会话真相源。它持有 `documentId`、来源类型、`mode: editable | external-readonly`、`revision`、`savedRevision`、当前画布、视图和异步 generation；UI 不直接改模型也不直接调用 SDK。内容命令完成后递增修订；当 `revision !== savedRevision` 时为脏。一次保存只把所写快照的修订记为已保存，若用户已产生后续修订，仍保持脏。

所有打开、切换、删除和离开动作经同一个“离开保护”协调：先提交正在进行的文字/IME 编辑，给当前会话与请求生成 token，脏时提供“保存、放弃、取消”。异步返回仅在 token 仍匹配且目标会话未变时提交。新打开的文件先在隔离缓冲区识别和解析，完成后才替换当前会话；取消、解析失败、授权失败或过期结果都不替换当前文档。

画布内核和格式解析器是待 PoC 选择的适配接口，不可由原型 HTML 或浏览器替身取代。PoC 应验证中文 IME、撤销/重做、缩放/拖拽、布局、画布生命周期、SVG/PNG 导出及插件 WebView 焦点；未通过前不承诺某一引擎或 `.smm`/`.xmind` 支持深度。

## 5. 文件、目录、会话与权限流程

### 5.1 工作目录

工作目录只用于用户主动选定目录内的 `.gxp` 列表、新建、保存和删除。首次或重新选择时，文件服务调用系统目录对话框；成功后将目录设置与授权分别写入 SDK，并以授权后返回的目录引用列举。启动恢复必须读取设置、验证 grant、再列举，验证失败时提示“重新选择目录”，保留仍在内存中的会话。不得持久化子目录引用、路径文本或过期 `FileReference`。

目录列表只将 `.gxp` 作为可编辑原生工作簿显示；外部文件由“打开文件”系统对话框导入或预览，不把工作目录扫描解释成已支持外部格式管理。删除目录文件使用 `directories.remove`，它由宿主移入系统回收站；调用前可取消，调用后禁用取消、遮罩关闭和返回编辑，直到结果返回。失败时保留列表项与内存文档，成功后才移除列表项并关闭会话。

### 5.2 打开、预览、副本与保存

| 触发 | 正式流程 | 成功后的会话 | 取消/失败 |
| --- | --- | --- | --- |
| 打开文件 / Cmd/Ctrl+O | 离开保护 → 文件选择（`.gxp/.smm/.xmind`）→ 读字节 → 格式服务识别、校验、隔离解析。 | `.gxp` 建立可编辑会话；外部来源建立只读预览会话和兼容报告。 | 不改变当前会话、选中项或脏状态。 |
| 新建 | 创建空白 `.gxp` 内存工作簿；用户命名后经目录保存或另存为。 | 可编辑、初始未保存。 | 取消命名/目标选择仅保留或放弃内存草稿，不伪称写盘。 |
| 外部编辑意图 | 在修改命令前确认“创建可编辑副本”；将已解析、可保留内容编码为新 `.gxp`，用另存为或受权工作目录创建。 | 仅新 `.gxp` 进入可编辑和脏状态；来源继续只读。 | 未生成副本不得执行内容修改。 |
| 保存 `.gxp` | 编码当前修订快照，调用被授权目标的 `writeFile`；无目标时转原生“另存为”。 | 对应快照标为已保存。 | 保留文档、修订和可重试状态。 |
| 导出 SVG/PNG | 先根据选择的画布/全部画布渲染交付字节，再为每个输出调用系统另存为及 `writeFile`。 | 显示逐项结果，不改变 `savedRevision`。 | 取消不改工作簿；部分成功逐项列出，允许重试失败项。 |

`FileReference` 是用户本次选择授权的能力而不是路径或永久身份。对同名/同目录文件不可凭文件名推断安全性；当 SDK 返回 `REFERENCE_EXPIRED`、`PERMISSION_DENIED`、`CONFLICT`、`IO_ERROR` 或 `FILE_TOO_LARGE` 时，显示可理解的错误和下一步（重选、另存、重试或缩小文件），同时保留可恢复内存文档。

## 6. 原生 `.gxp`、外部解析与兼容边界

`.gxp` 的正式格式是本产品需实现和验证的持久化合同，而不是原型现有能力。P0 需先完成版本化 schema、编码/解码、损坏与超限拒绝、未知字段策略、资源策略及“保存后关闭再打开”样本验证；随后才能把 `.gxp` 标为可保存功能。最低逻辑内容应有格式版本、工作簿元数据、稳定画布 ID 与顺序、每张画布的主题树/结构/主题设置、视图持久化边界，以及能产生兼容报告的来源元数据。具体封装形式和字段以 PoC 的可重开测试定稿，不在本草稿中伪造已存在的包格式。

外部格式实行下表边界：

| 格式 | 打开 | 编辑 | 保存 | 导出 | 实施前置条件 |
| --- | --- | --- | --- | --- | --- |
| `.gxp` | 正式目标 | 正式目标 | 覆盖同一原生文件或另存 `.gxp` | SVG/PNG | 编解码与重开测试通过。 |
| `.smm` | 外部只读预览目标 | 只可创建 `.gxp` 副本后编辑 | 不写回 `.smm` | SVG/PNG（从预览/副本的可渲染内容） | 用真实样本建立解析范围、丢失项和错误报告。 |
| `.xmind` | 外部只读预览目标，含已有画布切换 | 只可创建 `.gxp` 副本后编辑 | 不写回 `.xmind` | SVG/PNG（同上） | 验证多画布、未知元素、损坏包与许可/依赖。 |

这里的“目标”不是完成声明。浏览器原型只会把用户选中的文件映射为同格式样例树；它没有真实 `.smm`/`.xmind` 二进制解析，也没有真实 `.gxp` 包或磁盘写入。正式实现不得以该行为替代真实样本验收，也不得承诺富文本、附件、关系、概要、边界、自由主题、布局或未知元素的无损保留。格式服务必须对每份外部文件输出“可编辑保留、仅可预览、将转换、无法保留”的具体报告；不能识别则拒绝副本创建而非默默丢弃。

## 7. 画布 / 大纲 / UI 实现契约

### 7.1 布局、层级与状态

- 根容器固定在宿主 iframe 的可用高度，`overflow: hidden`；画布是唯一主要滚动/平移区域。实际溢出的侧栏/对话框可独立滚动，并使用研发指南规定的 6px 系统风格滚动条，避免 body、根和列表出现多重滚动。
- 无顶部标题栏。左上主菜单 z-index 低于展开的左侧覆盖面板；右上保存/导出高于画布但不在主菜单复现。模态再高于一般覆盖面板，并有遮罩与焦点约束。
- 左缘缩略标记只反映当前可见分支：主题增删、折叠与展开即时同步。鼠标进入标记区才显示完整侧栏，离开收起；侧栏不改变画布宽度。
- 侧栏内“文件”和“大纲”是互斥的等宽次级 Tab，共享 1px 底线；选中项使用铺满单元格的 2px 指示条，无卡片式选中填充。主题文字选中节点；前置箭头是独立的展开/折叠控件。
- 左右结构中根主题提供左右独立的折叠控制；向下结构使用底部单一控制。折叠只影响相应可见分支，不删除模型。
- 选择节点后才显示上下文工具条；点“样式”才打开属性面板。属性、抽屉和模态是互斥状态机，关闭后把焦点还给仍可用的触发控件。

### 7.2 命令语义

| 命令 | 模型/历史 | 视图 | 脏状态 |
| --- | --- | --- | --- |
| 重置视图 | 不写模型、不入撤销栈 | 恢复默认缩放和位置 | 不变 |
| 重置画布 | 保留根主题，移除其他分支；一个可撤销命令 | 保持当前缩放和位置 | 变脏 |
| 新建/改名/移动/折叠内容 | 通过命令服务更新模型；可撤销（视图态折叠除外时需明确） | 按命令更新 | 变脏 |
| 导出 | 不更新工作簿模型 | 不变 | 不变 |

画布获焦且无文字输入或中文组合输入时，`Tab` 新建子主题，`Enter` 新建同级主题；双击节点或画布标签开始命名，`Enter`/失焦确认、`Esc` 取消。`Cmd/Ctrl+S` 保存、`Cmd/Ctrl+Z` 撤销、`Cmd/Ctrl+O` 打开；`Esc` 的优先级为当前可取消浮层、属性/目录、选区。删除请求已经发出时，Esc/遮罩/取消不得解锁或撤回请求。

### 7.3 视觉与可访问性

配色采用宿主暖色基底和克制的紫色交互锚点：工作台可用 `#F5EFE4`，交互/选中可用 `#7656A7`，小面积焦点可用 `#B69CFF`，危险/失败使用 `#D36C6C`；每个实际文字和图形焦点组合在实现时逐一测量对比度。颜色仅是状态辅助，选中、错误、禁用还需边框、图标或文本。

画布之外必须提供同步、可键盘遍历的大纲树，供读屏和深层定位；所有图标按钮有中文可访问名称和悬停提示。焦点顺序应在主菜单、侧栏、画布、属性、画布标签和模态之间可预测；模态关闭、侧栏收起、错误重试后均恢复合适焦点。桌面目标宽度为 1440px，至少支持 900px；窄于该范围可横向滚动，不以压缩节点文字伪造适配。

## 8. 状态、错误、可访问性与安全

状态机至少区分 `editable-clean`、`editable-dirty`、`external-readonly`、`saving`、`opening`、`deleting`、`error`。忙状态明确对象和可取消性：打开/保存失败可重试；删除发出后锁定直到 SDK 返回。任何未支持能力都显示解释，不能静默成功；通知可作为补充，不能替代错误正文或状态文本。

安全措施包括：只以 SDK 引用调用文件和目录；格式解析隔离在提交会话前；错误信息通过 Vue 文本绑定呈现，不拼接 HTML；仅记录必要的诊断信息，避免记录文件字节、路径或私密标题。原型的 `postMessage` 仅用于研发观察，且它已限制当前 iframe source、以 `textContent` 渲染；正式插件不把它当宿主协议或文件桥接。

发布前必须至少验证：

1. `initTreasure()` 先于 Vue 挂载，正式依赖与锁文件解析为 2.1.1，且不用 Tauri/私有协议。
2. 系统打开、取消、读取失败、Unicode 文件名、32 MiB 超限；用户取消不会替换现有会话。
3. 系统另存为、用户改名、写入失败、多画布部分导出；导出不改变脏状态。
4. 目录初选、重启恢复、授权撤销、目录不可用、重选；无绝对路径或失效引用持久化。
5. `.gxp` 新建—保存—关闭—重开；外部 `.smm/.xmind` 只读、修改时副本确认、绝不回写。
6. 左侧浮层层级、无顶部栏、保存/导出唯一入口、无侧栏新建；键盘、读屏与焦点归还。
7. 重置视图不改变节点/历史/脏状态；重置画布保根、保视图、可撤销且变脏。
8. 打包产物根目录具备入口、静态资源、`manifest.json` 和 `scripts/`，并在桌面宿主注册调试与导入验证。
