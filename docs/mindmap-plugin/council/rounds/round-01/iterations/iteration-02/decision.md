**必要修订：**将“取消保证不调用删除并恢复编辑”限定为 `directories.remove` 调用之前。删除请求发出后应显示“正在移到回收站”，取消入口关闭或禁用，继续保持编辑锁直到真实结果；成功后更新列表并关闭当前会话，失败后保留文件行和内存文档并解锁。此阶段的取消请求或 token 失效不得被当作 SDK 操作已撤回，也不得虚称原文件未删除。同步修正通用第 5 步、删除行、表后取消文案与验收场景；其他路径在提交前仍可取消。

**验收：**分开描述“remove 调用前取消”和“remove 已调用但未返回”：前者不调用删除，恢复编辑；后者不承诺撤回，保持锁，真实成功/失败分别处理，不能因取消提前解锁或把迟到成功报告为取消成功。只需完善方案，不要求现在实现或执行该测试。
