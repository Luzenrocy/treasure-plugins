## Findings

### R1-001 — P1 — 离开会话只等待保存成功，可能丢失保存期间的新修订

- **位置：** `draft.md` §7.2，第 218–220、225、227 行；对应 §9.3 第 319–320、323 行。
- **证据：** 第 220 行明确保存快照为修订 N，保存期间新增 N+1 仍为未保存；但第 219 行把关闭成功条件写成“保存成功，或明确选择放弃”，第 218 行的“保存并打开”和第 225 行的“另存成功才继续回收原文件”同样没有要求离开前重新检查当前修订。第 227 行只串行化离开命令，没有阻止正文编辑。第 319 行也允许“保存成功才提交 B”，第 320 行仅检查 N+1 仍脏，未检查随后的离开是否被拦截。
- **影响：** A 为修订 N 时选择保存并打开 B；保存过程中产生 N+1；N 写入成功后，按当前成功条件可提交 B 并销毁仍脏的 A。关闭、换目录、另存后删除也会遇到同类窗口。把 N+1 正确标脏本身不能阻止数据丢失，影响 U-006、U-007、U-009、U-011 的未保存保护。
- **行动：** 明确一个通用的 leave guard。可选择离开流程中先提交当前文本/IME 编辑，再锁定内容命令直到完成；或允许继续编辑，但保存结束后、任何会话替换/销毁/删除提交前，再原子检查会话身份及 `currentRevision == savedRevision`。仍有新修订时重新保存/重新提示/取消离开；只有针对最新状态的明确放弃可以跳过保护。将此规则用于打开、关闭、切换目录和另存副本后删除，不能以任意一次写成功等价于会话可安全离开。
- **验收：** 补充方案级可执行场景：暂停 A 的 N 写入，在等待期间输入 N+1，再返回 N 保存成功；尝试打开 B、关闭、换目录及另存后删除四条路径。每条要么编辑已被明确锁住，要么保留 A/N+1 并继续保护，不能自动销毁。确认保存的是当前修订后才可离开；若用户明确放弃最新修订则允许继续。相应更新 §7.2、§9.3 与 coverage 的证据描述。本次只需把规则和门槛写清，无须实现 PoC。
