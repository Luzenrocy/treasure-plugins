# Treasure 宿主视觉参考

> 本文是面向插件开发者的**宿主视觉适配参考**，不规定插件的业务视觉方案。每个插件仍应在自身 README 中定义并维护独立的颜色配比。

## 1. 宿主视觉气质

Treasure 宿主采用“暖调毛玻璃文人雅致”风格：暖米色内容区、深紫导航、暖金品牌点缀，强调舒缓、克制与本地工具的可靠感。插件页面无需复制宿主导航，但应避免与宿主框架产生突兀的冷白、荧光或过度高饱和冲突。

## 2. 宿主色彩锚点

| 角色 | 色值 | 对插件的参考意义 |
| --- | --- | --- |
| 内容基底 | `#F5EFE4` | 适合作为温暖浅色页面的协调基底。 |
| 标签表面 | `#ECE3D3` | 适合次级工具栏、轻量分区。 |
| 导航深紫 | `#3D3450` | 宿主结构色，不建议在插件中大面积复用。 |
| 导航文字 | `#C9B8D9` | 深色表面上的弱强调文字。 |
| 交互紫 | `#7656A7` | 可作为偏雅致插件的主操作或选中态。 |
| 亮紫 | `#B69CFF` | 仅用于小面积高亮和焦点提示。 |
| 暖金 | `#E8C98A` | 品牌性与次级强调；不应用作常规正文颜色。 |
| 危险色 | `#D36C6C` | 删除、错误与高风险状态。 |

## 3. 适配原则

- **层级先于装饰**：用留白、字体、表面深浅和状态区分信息，再使用颜色。
- **业务可以有独立主色**：例如任务类插件可采用 Indigo；但应说明它与宿主紫金色的关系，并在同一插件内保持一致。
- **大面积表面保持温和**：浅色界面优先暖白、米色或低饱和色，不使用纯白与冷灰的大块背景。
- **语义颜色稳定**：成功、警告、危险应保持一致含义，不能仅为装饰而改变语义。
- **避免双重导航感**：插件内的侧边栏、标签和工具栏应服务自身任务，不要与宿主外壳争夺层级。

## 4. 插件 README 必备的色彩说明

每个插件 README 至少应包含：

1. 主色及它表达的产品性格；
2. 页面背景、文本与边界色；
3. 成功、警告、危险和优先级等语义色；
4. 与 Treasure 宿主的协调策略；
5. 颜色的实际使用位置，而不只列出色值。

这份参考不会替代插件自己的设计文档；它只帮助插件在同一工作区中保持整体体验的连续性。
